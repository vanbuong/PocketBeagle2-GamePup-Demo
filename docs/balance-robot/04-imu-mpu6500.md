# 4. MPU6500 handling and sensor data processing

All register values below are from the InvenSense MPU-6500 register map as remembered
during design; **verify each against the datasheet** (PS-MPU-6500A, RM-MPU-6500A) when
writing the driver. The driver has a unit test that asserts the init sequence against a
register-level mock so an incorrect constant is caught on the host.

## 4.1 Part facts

| Item | Value |
|---|---|
| Axes | 3-axis gyro + 3-axis accel + temperature (no magnetometer; MPU-9250 is the 9-axis sibling) |
| WHO_AM_I (0x75) | **0x70** (MPU-6050 reads 0x68, MPU-9250 0x71) — probe must accept only 0x70 and log others |
| Gyro full scale | ±250/500/1000/2000 °/s → 131 / 65.5 / 32.8 / 16.4 LSB/(°/s) |
| Accel full scale | ±2/4/8/16 g → 16384 / 8192 / 4096 / 2048 LSB/g |
| Temp | °C = raw / 333.87 + 21 |
| Interfaces | I²C up to 400 kHz, SPI mode 0 or 3; SPI up to 1 MHz for config registers, **up to 20 MHz for sensor/interrupt registers** |
| Noise (typ.) | gyro ≈ 0.01 °/s/√Hz, accel ≈ 300 µg/√Hz |
| Zero-rate offset | gyro initial ≈ ±5 °/s, drifts with temperature — must be calibrated |

Choices for this robot: **±1000 °/s gyro** (a falling robot rotates fast; ±500 would be
enough for normal operation but clips in a hard fall; resolution 0.03 °/s per LSB is still
far below the noise), **±4 g accel** (the gravity reference matters at low acceleration;
8192 LSB/g), 16-bit raw to `float`.

## 4.2 Bus choice: SPI

| | I²C 400 kHz | SPI 4 MHz *(initial)* |
|---|---|---|
| 14-byte burst (accel+temp+gyro) | ≈ 380 µs incl. addressing | ≈ 30 µs |
| Bus load at 1 kHz | ≈ 38 % | ≈ 3 % |
| Pins | 2 (shared) | 4 + CS |
| Robustness | clock stretching/stuck bus risk | simple, no stuck-bus recovery |

SPI is the primary interface. The driver supports I²C as a build option (many cheap GY-6500
breakouts expose only I²C; select a board that breaks out NCS/SCL(SCLK)/SDA(SDI)/AD0(SDO)).
SPI wiring: keep SCLK/MOSI/MISO/INT traces short, 3.3 V logic (the part is not 5 V tolerant),
100 nF + 10 µF decoupling at VDD, mount the IMU rigidly near the wheel axis centre-line to
minimise lever-arm acceleration, away from the motors and wires (magnetic field is
irrelevant for 6-axis, vibration is not).

Sensor mounting: define the body frame **x forward, y left, z up**. The driver has a
compile-time rotation matrix `R_body_sensor` (one of 24 axis permutations) so the board can
be mounted in any orientation; unit-tested for all 24.

## 4.3 Initialisation sequence

```
1. delay 100 ms after power-up
2. USER_CTRL (0x6A)       = 0x10   (I2C_IF_DIS: SPI only) — first write, 1 MHz max clock
3. PWR_MGMT_1 (0x6B)      = 0x80   (DEVICE_RESET), wait 100 ms
4. USER_CTRL              = 0x10   again (reset re-enables I2C interface)
5. SIGNAL_PATH_RESET 0x68 = 0x07   (reset gyro/accel/temp paths), wait 100 ms
6. PWR_MGMT_1             = 0x01   (clock = PLL with X gyro, sleep off), wait 10 ms
7. read WHO_AM_I          == 0x70 else FAULT_IMU_ID
8. PWR_MGMT_2 (0x6C)      = 0x00   (all axes on)
9. CONFIG (0x1A)          = 0x01   (gyro DLPF 184 Hz, 2.9 ms delay, Fs = 1 kHz)
10. GYRO_CONFIG (0x1B)    = 0x10   (±1000 °/s, FCHOICE_B = 0)
11. ACCEL_CONFIG (0x1C)   = 0x08   (±4 g)
12. ACCEL_CONFIG2 (0x1D)  = 0x01   (accel_fchoice_b=0, A_DLPF_CFG=1 → 218 Hz, Fs 1 kHz)
13. SMPLRT_DIV (0x19)     = 0x00   (1 kHz / (1 + 0))
14. INT_PIN_CFG (0x37)    = 0x30   (active-high, push-pull, LATCH_INT_EN=1 so INT stays high
                                    until cleared, INT_ANYRD_2CLEAR=1 so any register read
                                    clears it — the 14-byte burst therefore re-arms DRDY)
15. INT_ENABLE (0x38)     = 0x01   (RAW_RDY_EN)
16. switch SPI clock to 4 MHz (sensor-register reads only)
17. discard first 50 samples (settling)
```

Notes:

- With gyro DLPF 184 Hz the group delay is ~2.9 ms. DLPF 92 Hz (`CONFIG=2`, 3.9 ms) lowers
  noise at the cost of phase lag in the balance loop; start at 184 Hz and treat as a tuning
  parameter alongside the loop gains (doc 5).
- Config registers must be written at ≤ 1 MHz; the driver keeps two SPI configs.
- A 1 kHz DRDY interrupt is the sample clock for the whole system (doc 1, 1.3).
- The accelerometer and gyro are sampled in the same internal cycle; the 14-byte burst
  starting at ACCEL_XOUT_H (0x3B) gives ax,ay,az,temp,gx,gy,gz in one transaction → samples
  are coherent. Never read them in separate transactions.

## 4.4 Read path

SPI frame: `tx = [0x3B | 0x80, 0 × 14]`, `rx[1..14]` data, big-endian 16-bit signed.

```c
typedef struct { int16_t ax, ay, az, temp, gx, gy, gz; uint32_t t_irq_cyc; } imu_raw_t;

static inline int16_t be16(const uint8_t *p) { return (int16_t)((p[0] << 8) | p[1]); }

void imu_parse(const uint8_t rx[15], imu_raw_t *o) {
    o->ax = be16(&rx[1]);  o->ay = be16(&rx[3]);  o->az = be16(&rx[5]);
    o->temp = be16(&rx[7]);
    o->gx = be16(&rx[9]);  o->gy = be16(&rx[11]); o->gz = be16(&rx[13]);
}
```

Timestamping: the ISR records the cycle counter (DWT CYCCNT) at DRDY; `dt` for integration
uses the **measured** sample interval filtered with a moving average (clamped to
0.5–2 ms), not the nominal 1 ms. The MPU6500's clock is within ±1–3 % of nominal; the
measured `dt` removes a gain error in the integrated angle, which the 1 kHz DRDY pacing
already makes small. A missed DRDY is detected from `dt > 1.5 ms` and counted.

Health checks per sample (any failure increments a counter, 3 consecutive = fault):
- all-0x00 or all-0xFF frame (bus fault),
- raw value stuck (identical 14 bytes for 50 samples),
- |a| outside 0.5–2.5 g while motionless (sensor fault, not dynamics),
- data-age > 3 ms.

## 4.5 Unit conversion and mounting

```
a_body  = R * (a_raw / 8192)               [g]
w_body  = R * (g_raw / 32.8) * (π/180)     [rad/s]
T_C     = temp_raw / 333.87 + 21
```

## 4.6 Calibration

### Gyro bias (every boot, in `STANDBY`)

1. Require the robot to be still: running variance of gyro < threshold (≈ 0.5 °/s) over
   the window and accelerometer magnitude within 0.97–1.03 g.
2. Average 1024 samples (≈ 1 s) per axis → `b_g` (float). If the window is disturbed
   restart; abort with `CAL_FAIL` after 10 s.
3. Store `b_g` and the die temperature `T0`.

### Online bias tracking (while `STANDBY` or while balancing and stationary)

Zero-velocity detector: wheel speeds ≈ 0 (PRU encoders) and |ω| < 1.5 °/s and no commanded
motion for 2 s → slowly update `b_g ← b_g + k·(w_meas − b_g)` with k ≈ 0.001 per sample
*(initial)*. Pitch rate bias is also observable inside the Kalman filter (4.8 option B).

### Temperature compensation (optional, M3)

Measure gyro zero-rate vs. temperature (heat/cool the board 20–50 °C, log 300 s per point),
fit `b_g(T) = b0 + b1·(T − T0)` per axis (linear is enough). Stored in settings.

### Accelerometer

- **Level calibration (v1):** place the robot on a flat surface in the nominal balance
  pose; average 2 s; store offsets for ax, ay (and gravity-direction trim → `θ_trim`).
- **6-position (v2):** ±x, ±y, ±z up, each averaged 2 s. Solve for per-axis offset `o` and
  scale `s` (and optionally a 3×3 misalignment) by least squares with the constraint
  |a| = 1 g. Stored in settings. Offsets in the chip's own registers (0x77–0x7E) are not
  used, so firmware owns all calibration and it is host-testable.
- **Self-test** (`SELF_TEST_X/Y/Z_GYRO` 0x00–0x02, `SELF_TEST_X/Y/Z_ACCEL` 0x0D–0x0F)
  on demand, outside `BALANCING`; result reported in `CAL_RESULT`.

### Balance-point trim

The mechanical centre of gravity is never exactly over the axle. `θ_trim` is the pitch at
which the robot balances without drifting; it is found at setup (hold at the point of
least motor effort) and refined continuously by the slow integral of the outer speed loop
(doc 5, 5.7).

## 4.7 Filtering chain

```
 raw → scale/axis-map → bias/scale/offset → (optional 2nd-order IIR on accel) → attitude
```

- **Gyro**: no extra filter beyond the on-chip DLPF in the control path (every filter
  adds lag inside the unstable loop). A separate 100 Hz-notch/low-pass copy is made only for
  vibration diagnostics and fault detection.
- **Accel**: needed only for the slow gravity reference, so a 2nd-order Butterworth low-pass at
  ~10–20 Hz (biquad, 4 multiplies/sample) is fine because the complementary filter
  de-emphasises it. It also removes motor/gear-mesh vibration.
- **Accel validity gate**: the accel pitch is trusted only when `| |a| − 1 g | < 0.1 g` and
  the wheel acceleration is small. When the robot accelerates, the accelerometer reads
  gravity **plus** linear acceleration, so `atan2(ax, az)` is wrong by `atan(a_lin/g)`.
  When invalid, accel gain → 0 and the gyro integrates alone.

## 4.8 Attitude estimation

The balance loop needs: pitch θ and pitch rate θ̇ (about the axle), and yaw rate ψ̇. Three
estimator options are specified; **A is implemented first, B and C are alternatives
compared in simulation (doc 6, SIM-3).**

### A. Complementary filter (pitch only) — baseline

```
θ_acc  = atan2(−a_x, a_z)                     // body x forward, z up, pitch > 0 = leaning forward; rad
θ[k]   = α · (θ[k−1] + ω_y · dt) + (1 − α) · θ_acc
α      = τ / (τ + dt)                          // τ ≈ 4 s with a 0.03 g validity gate gave the best result in simulation (doc 5.12): while accelerating the accelerometer
                                               // reads gravity plus acceleration, and τ = 1 s let 3 deg of error through; α = τ/(τ+dt) ≈ 0.99975 at 1 kHz
θ̇      = ω_y − b_y                             // the corrected gyro rate is the rate used by D term
```

Costs ~20 flops. `(1 − α)` is multiplied by the accel validity weight `w ∈ [0, 1]`
(4.7) so accel is ignored during hard acceleration.

### B. Two-state Kalman filter (pitch + gyro bias)

State `x = [θ, b]ᵀ`, input = gyro rate `ω`, measurement = accel pitch `z`.

```
Predict:   θ ← θ + dt·(ω − b)            P ← F P Fᵀ + Q
           F = [[1, −dt], [0, 1]]
           Q = [[Qθ·dt, 0], [0, Qb·dt]]          Qθ ≈ 1e-3..1e-2 rad²/s, Qb ≈ 1e-6..1e-5
Update:    y = z − θ;  S = P00 + R;  K = [P00, P10]/S
           θ ← θ + K0·y;  b ← b + K1·y;  P ← (I − K H) P        H = [1, 0]
           R = accel pitch variance, ~(0.5°)² nominal, inflated ×100 when accel invalid
```

Advantages: bias estimated online, optimal weighting. Cost ≈ 40 flops. Needs numeric care:
use the symmetric Joseph form or clamp `P` diagonal ≥ 0 in float32.

### C. Mahony / Madgwick quaternion (full 3-D)

Gives pitch, roll and yaw-rate-consistent gravity vector; Mahony with `Kp≈0.5–2, Ki≈0.0–0.05`
(6-axis, no magnetometer). Needed if the robot must handle ramps/side slopes or roll
(e.g. when driven onto a kerb). Cost ≈ 150 flops, still under 2 µs at 400 MHz. Pitch is
extracted as `asin(2(q0 q2 − q3 q1))` with the project's axis convention.

### Yaw rate and heading

`ψ̇ = ω_z − b_z` is used directly for the steering loop (no heading integration needed for
joystick driving). A relative heading is integrated on request (e.g. "turn 90°") and
stabilised with wheel odometry: `ψ̇_enc = (v_R − v_L)/track`. A 1-state complementary blend
`ψ̇ = 0.98 ω_z + 0.02 ψ̇_enc` (initial) tolerates gyro bias without drift in long spins.

### Wheel-speed fusion

`v = (v_L + v_R)/2` from PRU0 counts at **100 Hz** (with the M/T edge-timestamp method at low speed; with
JGB37-520 1:30 one count is 0.155 mm, so a 2 ms window is far too coarse, doc 8.1) (`v_wheel = 2π r · Δn / (CPR_eff · Δt)`), low-pass at
~15 Hz. The *body* speed relevant to the pendulum is `v_wheel − r θ̇` (wheel speed relative
to the ground minus the swing of the body); the controller uses `ẋ ≈ v_wheel`
and relies on the gyro for tilt rate, matching the state vector in doc 5.

## 4.9 Data validation and fallbacks

| Situation | Estimator behaviour |
|---|---|
| accel invalid (hard acceleration, fall) | gyro-only integration; accel gain 0 |
| gyro saturation (|ω| ≥ 95 % of FS) | flag `GYRO_SAT`; hold last good rate for ≤ 5 ms, then fault |
| IMU communication lost (stale > 3 ms) | motors → brake, state FAULT |
| tilt > 35° | FALLEN; the estimator keeps running for recovery detection |
| large θ_acc vs θ disagreement for > 1 s | log `EST_DIVERGE`; re-initialise from accel only when stationary |

## 4.10 Python reference implementation and test vectors

`tools/imu_ref.py` implements the same driver-level conversions, filters A/B/C in NumPy;
`sim/` replays recorded or synthetic IMU streams through both the C core (via `ctypes`)
and the Python reference and asserts they agree to 1e-4 rad. Golden vectors include:
static (bias only), constant-rate rotation, sinusoidal tilt at 0.5/2/5 Hz, accel spikes,
bias step, saturation, and a recorded fall.
